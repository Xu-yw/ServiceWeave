# 测试用例

本目录按评测类型分类。数据版本仍为 v2，已完成 2026-09-25 的一轮评测；本次仅整理目录，不改问题、标签、检查项或参考知识。

## 意图识别

位于 [意图识别/](意图识别/)：

- [意图开发集请求.json](意图识别/意图开发集请求.json)：150 条开发样本，每条包含用户问题与预期意图。
- [意图验收集请求.json](意图识别/意图验收集请求.json)：50 条预留验收样本。
- [拆分清单.json](意图识别/拆分清单.json)：开发与验收样本的固定 ID 划分。

合计 200 条、19 类。评测指标为 Accuracy、Macro-F1 和逐类 Precision/Recall/F1。验收集已使用，不再属于未来调参的未见数据。

## 对话质量

位于 [对话质量/](对话质量/)：

- [对话评测请求.json](对话质量/对话评测请求.json)：30 组、60 轮对话，包括逐轮问题、关键检查项与参考上下文。
- [参考知识快照.json](对话质量/参考知识快照.json)：6 篇参考知识，用于核对知识库及提供 Judge 评分依据。

单轮、双轮、三轮各 10 组。逐轮四维均分 ≥ 0.75 且关键项全部满足才通过。参考知识与检查项仅传 Judge，不注入业务 Agent；评分失败不参与均分，但计入通过率分母。

## 共用资料

- [样本审阅.md](样本审阅.md)：两类测试用例的完整可读清单；文中“意图样本”和“对话样本”分别列出对应内容。
- [共用资料/样本与标注.json](共用资料/样本与标注.json)：两类样本的完整标注、来源和元信息，供结果追溯。
- [共用资料/静态校验结果.json](共用资料/静态校验结果.json)：样本构造时的数量、类别覆盖、去重等校验记录。
- [冻结清单.json](冻结清单.json)：当前文件路径与 SHA-256，运行脚本据此校验。

样本为合成数据，尚无独立人工盲标。共用资料中“未运行”等描述是样本构造时的记录；当前运行方法和限制见 [评测模块说明](../README.md)。本仓库不包含个人历史运行记录；问题、标签、检查项和知识内容沿用已有测试集。

## 标注边界


同一句只标当前主要诉求；明确的退款、发票、支付异常等具体类别优先于query、request、billing等通用类别。多个需要分别处理的诉求放在对话中，不强行给复合诉求打一个标签。

|容易混淆的类别|本版本判定约定|
|---|---|
|order_status／logistics|订单是否生成、备货、出库、取消属于前者；在途轨迹、配送时段、运费及末端配送属于后者|
|request／logistics|未发货时修改收件信息归request；进入配送后的末端投递安排归logistics|
|complaint／human_handoff／escalation|表达不满、要求普通人工、要求主管或更高层级复核分别对应三类|
|billing／payment_issue／refund／invoice|计费口径与账单解释、实际支付异常、退货退款、开票及票据更正分别处理|
|account／account_security／technical_login|账户资料设置、异常访问或凭证保护、无法完成登录认证分别处理|
|technical／technical_crash|一般功能或性能故障归technical；闪退及HTTP500按本项目固定定义归technical_crash|
|query／billing|普通商品、会员与优惠规则咨询归query；既有账单构成、订阅计费口径归billing；原I001标签保留，不按已有预测改标|
|feedback／greeting／other|明确正向服务反馈、普通问候、无业务诉求或缺上下文无法识别分别处理|

旧I001、I006、I018等有争议的边界样本仍保留原标签和理由。若审阅后需要变更标签，建立新版本并重算对应成绩，不能回写旧运行结果。
