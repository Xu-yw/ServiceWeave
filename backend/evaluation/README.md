# ServiceWeave 评测

## 两类测试

- [意图识别](测试用例/意图识别/)：200 条、19 类，开发集 150 条，预留验收集 50 条；比较预测与标签，计算 Accuracy、Macro-F1 和逐类 Precision/Recall/F1。
- [对话质量](测试用例/对话质量/)：30 组、60 轮；逐轮调用 Orchestrator，并传递实际历史。Judge 结合参考知识，对相关性、准确性、完整性、有用性评分，同时判断关键项。

四维均分 ≥ 0.75 且关键项全部满足才通过。解析或结构错误最多重试一次，低分不重试；最终评分失败不参与均分，但计入通过率分母。参考知识和检查项仅给 Judge，不注入业务 Agent。

## 运行

按 [项目说明](../../README.md) 启动服务，在仓库根目录执行：

```bash
python backend/evaluation/运行评测.py
```

脚本校验样本哈希、实时知识库和运行源码，按 25 条意图一批、每组对话一次请求保存输入、实际回复、评分、源码与配置。实际评测会调用模型。后端地址不是本机 8000 时，设置 `SERVICEWEAVE_API_URL`。

结果位于 `backend/evaluation/结果/<时间戳>-v2/`。运行前重启后端清除进程内意图缓存，期间避免其他聊天请求；工具缓存仍用默认 TTL。脚本关闭旧基线比较与写入。

```bash
python backend/evaluation/生成报告.py backend/evaluation/结果/<时间戳>-v2
```

结果目录默认不提交。报告分别汇总两类指标，不将 API 的混合通过率误作意图准确率。

## 边界

样本为合成数据，未经过独立人工盲标；预留验收集已使用，不再是未来调参的未见数据。Judge 与业务 Agent 使用同一配置模型，评分需抽查，不能等同线上效果。

对话评测直接调用编排器，不覆盖 `/chat` 的持久化记忆读写；评测入口未传实体，编排器识别后也未回填，可能影响交接用例。需区分业务回答不合格与 Judge 输出解析失败。

更名后尚未重新调用模型评测。冻结清单针对当前发布文件，问题、标签、检查项和知识内容沿用已有测试集。
